## 1. 目标与边界

在现有课表网站内，支持实验室成员发布任务、领取或接受指派、提交成果，并由发布者验收。公告任务用于公开招募执行成员；指定任务用于安排个人、多人或多个项目小组。

v2新增任务协作、任务附件、成果附件和站内消息；2026-10-08补充确认成员工作展示，具体增量见第16节。不改变课程所有权、共同空闲算法、课表导入规则和现有项目小组的管理权限。

本文件是v2增量需求，不代表当前生产环境已经具备这些能力。现有功能基线见[01-PRD.md](01-PRD.md)。已在[02-DATABASE.md](02-DATABASE.md)、[03-API.md](03-API.md)和AGENTS.md补齐增量契约；实现与验证进度见[07-TASKS.md](07-TASKS.md)。

### 1.1 本次包含

- 公告任务和指定任务的发布、查看、要求修改、执行对象调整。
- 公告领取、人数上限或不限人数、发布者结束领取。
- 指定个人、多人、一个或多个项目小组；个人与小组可以混选。
- 共同交付或逐人交付，由发布时选择。
- 文字、链接和小文件成果；提交历史、验收通过、打回、重新提交。
- 任务撤销、已完成或已撤销任务重新开启，多轮历史保留。
- 站内消息、未读状态、进入网站后的指派提醒弹窗。
- 游客仅查看任务列表。
- 成员页面保留课表，同时展示本人填写的文字工作记录和承担的近期任务；个人记录仅注册成员可见，由本人增删改，详见第16节。

### 1.2 本次不包含

- 邮件、微信或其他站外通知，自动截止提醒和实时推送。
- GitHub等代码平台自动读取、仓库授权、代码托管；commit仅作为普通链接提交。
- 根据课表自动分派任务、自动排期、会议室预订。
- 评论聊天、任务评分、排行榜、奖励、子任务、周期任务和任务模板。
- 全站管理员、跨用户撤销权限、独立任务管理后台。
- 独立会议纪要模块、个人工作记录附件、个人工作评论、个人工作记录的额外提醒和回收站。
- 课表版本回退、调课日期例外等原有后续路线。

## 2. 用户和权限

权限由服务端会话判断。所有注册成员具有相同的发布资格；发布者和执行成员是相对于某项任务的身份，不是全站角色。

| 操作或资料 | 游客 | 注册成员 | 当前执行成员 | 任务发布者 |
| --- | --- | --- | --- | --- |
| 任务列表 | 只读，字段受限 | 可查看全部任务 | 同注册成员 | 同注册成员 |
| 任务详情、执行名单、要求附件 | 不可访问 | 可查看 | 可查看 | 可查看 |
| 成果、提交历史、验收反馈、成果附件 | 不可访问 | 可查看及下载 | 可查看及下载 | 可查看及下载 |
| 发布新任务 | 不可 | 可以 | 可以 | 可以 |
| 领取开放的公告任务 | 不可 | 可以 | 不可重复领取同一任务 | 依同一领取规则 |
| 提交成果 | 不可 | 非执行成员不可 | 按交付模式提交 | 仅发布者身份不授予提交权 |
| 修改要求、调整执行对象、结束领取 | 不可 | 仅本人发布的任务 | 仅本人发布的任务 | 可以 |
| 验收、打回、撤销、重新开启 | 不可 | 仅本人发布的任务 | 仅本人发布的任务 | 可以 |
| 个人消息、消息已读操作 | 不可 | 仅本人 | 仅本人 | 仅本人 |

补充说明：

- 所有注册成员均能查看所有任务和成果，包括完成、撤销以及历史轮次；只有有关人员可执行对应写操作。
- 游客指已进入现有游客模式的访问者，普通匿名访问不因此自动获得权限。
- 游客任务列表只返回标题、发布者展示姓名、截止时间、状态和导航所需的任务标识，不返回描述摘要、执行名单、提交数量、成果、附件或消息。
- 游客列表不提供详情入口；直接访问详情、历史、下载地址或相应接口也必须被拒绝。展示成员学号时继续脱敏，列表默认不展示学号。
- 任务正文、提交版本、附件下载均须检查权限，不能只隐藏页面按钮。
- 原有课程只能由本人修改。任务发布者不能借助任务权限修改他人课程或他人项目小组。

## 3. 发布任务

### 3.1 任务信息

| 字段 | 规则 |
| --- | --- |
| 标题 | 必填，说明要完成的工作 |
| 任务说明 | 必填，说明工作内容及交付要求 |
| 类型 | 公告任务或指定任务 |
| 交付模式 | 共同交付或逐人交付 |
| 截止时间 | 可选，使用北京时间展示和输入 |
| 任务附件 | 可选，用于提供要求、资料或模板 |
| 公告人数 | 公告任务设置人数上限，或选择不限人数；上限为1时是单人任务 |
| 指定对象 | 指定任务至少选择一名可执行的注册成员，可通过个人和小组组合得到 |

发布者由会话确定，不接收客户端指定的发布者身份。任务可以没有截止时间；逾期只是标记，不禁止领取、提交或验收，未结束的任务仍按正常权限处理。

### 3.2 公告任务

- 面向注册成员开放领取，游客只能查看列表。
- 同一人不可重复领取，领取成功后直接成为执行成员。
- 发布者可设置人数上限，也可不限人数；单人任务最多一名当前执行成员。
- 达到人数上限时暂不可再领取。发布者移出成员释放名额后，若尚未结束领取，可以继续领取。
- 领取后成员不能自行退出，只能由发布者移出。
- 发布者可以添加、移除执行成员；手动添加和自行领取都受人数上限约束。需要增加人数时先调高上限，不能将上限调低至当前人数以下。
- 发布者必须明确“结束领取”，才允许任务进入最终完成状态。结束领取不阻止已有成员提交，也不禁止发布者调整名单。
- 结束领取时仍无人执行的任务不能直接判为完成；发布者需补充执行成员或撤销。

### 3.3 指定任务

- 可以选择单人、多人、一个项目小组或多个项目小组，也可以混选个人和多个小组。
- 指派直接生效，无需接受或拒绝步骤。提醒的“知道了”不是接受任务。
- 只纳入已注册且启用的成员；小组若包含不可执行成员，发布时明确说明其不纳入名单。
- 同一个人在多个目标来源中出现，只计一名执行成员。
- 发布者可以调整直接指定的个人以及目标小组集合。
- 小组任务内不能单独排除仍属于目标小组的人。要调整小组内部成员，须由有权限的组长操作原小组。
- 发布者选中了小组，不因此取得小组改名、成员维护、组长转让或解散权限。

## 4. 小组名单与人员变化

未完成、未撤销的指定任务，其当前执行名单等于“直接指定的启用注册成员”与“所有目标小组内的启用注册成员”的并集。

| 变化 | 任务处理 |
| --- | --- |
| 新成员加入目标小组 | 自动加入进行中的任务，收到指派提醒 |
| 成员退出一个目标小组 | 只有不再被其他目标来源覆盖时才移出任务 |
| 发布者移除直接指定的个人 | 若仍属于任一目标小组，仍是执行成员 |
| 发布者增加或移除目标小组 | 重新合并、去重当前执行成员 |
| 小组解散 | 去除该小组来源；由其他来源覆盖的人仍保留 |
| 成员停用 | 不再作为当前执行成员，保留相关历史 |
| 所有执行成员均被移出 | 任务保留，提示发布者重新安排或撤销，不能自动完成 |
| 任务已完成或已撤销 | 固定该轮结束时名单，不再自动跟随小组变化 |

成员被移出后不能继续提交或重提该任务，但此前成果不删除。逐人交付时，其已有成果仅作历史，不再计入当前完成条件。共同交付的成果属于本轮任务，提交人被移出不删除该成果。

人员变动应记录操作来源、时间和人员；不要通过改写历史记录伪装成“从未参与”。上述归档范围是业务历史，系统原始审计日志不对普通成员开放。

## 5. 成果提交和验收

### 5.1 提交方式

一次提交至少包含文字、链接、文件中的一种，可以组合使用。

- 文字：工作汇报、说明、README内容等。
- 链接：commit、仓库、网盘、外部文档等。系统保存并展示链接，不自动获取代码平台信息或外部文件。
- 附件：PDF、TXT、Markdown、PNG、JPG/JPEG、Word、Excel、PPT和CSV。具体扩展名默认见第11节。

限制：每次成果提交及每份当前任务要求最多5个附件，单个文件不超过10MB。10MB的准确字节上限须在界面和服务端保持一致，默认按10×1024×1024字节执行。

附件类型和大小必须由服务端校验，不能只按客户端提示放行；文件作为资料下载，不执行上传内容。上传失败、空间不足或提交失败时，须告诉用户如何重试、压缩文件或改用链接。

### 5.2 共同交付

- 任意当前执行成员都可提交或重提共同成果。
- 同一轮任务只有一个当前待验收版本，重提生成新版本，保留旧版本及提交人。
- 成果通过验收代表本轮共同交付通过，不要求每名成员单独提交。

### 5.3 逐人交付

- 每名当前执行成员提交自己的成果，不能替其他人提交。
- 每个人分别具有提交版本、待验收状态、通过状态和打回记录。
- 当前执行成员全部通过后，本轮满足成果完成条件；新增成员需提交并通过，移出成员不再阻塞完成。

### 5.4 重提、验收与打回

- 通过验收前，执行成员可随时重新提交，无需等待打回。
- 每次重提产生新版本，旧版、提交时间、提交人和已有反馈保留。
- 只有发布者可以验收或打回；打回必须填写原因。
- 发布者必须对当前最新版本操作；查看旧版期间发生重提时，不可误通过或误打回旧版，须刷新后再处理。
- 通过后，本轮对应成果不能继续重提。需要新的工作时由发布者重新开启任务，产生新一轮。
- 重复点击提交、领取或验收不得产生重复记录；并发操作不能绕过人数限制或最新版本检查。

## 6. 状态、撤销与重新开启

### 6.1 状态表达

任务整体状态与个人成果状态分开，避免一个“已提交”掩盖其他人尚未提交。

| 层级 | 用户可见状态 |
| --- | --- |
| 任务整体 | 进行中、已完成、已撤销 |
| 公告领取 | 领取开放、名额已满、领取已结束 |
| 当前成果或个人成果 | 未提交、待验收、被打回、已通过 |
| 截止时间标记 | 无截止时间、未逾期、已逾期 |

指定任务满足本轮成果完成条件后进入已完成；公告任务还须已结束领取。空名单不满足完成条件。任务详情应解释当前阻塞原因，例如“仍开放领取”“还有2人未通过”。

### 6.2 修改任务要求

- 发布者可修改进行中任务的标题、说明、截止时间和任务附件。
- 修改保留变更记录，并向当前执行成员发送站内消息；旧任务附件随旧要求保留。
- 要求修改不自动撤回本轮已有通过记录。这是补充默认，若要求变化需要全员重新交付，应结束当前轮后重新开启，或另发任务。
- 已完成、已撤销任务保持该轮记录不变；需修改时先重新开启。
- 类型、交付模式发布后固定。这是补充默认，需更换时新建任务，避免把进行中的成果临时改变为另一种验收单位。

### 6.3 撤销

- 只有发布者可以撤销自己发布的任务，撤销前二次确认。
- 进行中任务可撤销；已完成任务保留完成事实，不直接改为撤销。这是补充默认，已完成任务需继续处理时使用重新开启。
- 撤销后停止领取、提交、验收及名单自动跟随，保留要求、名单、成果、附件和反馈。
- 通知当前执行成员；其他注册成员仍可查看撤销历史，游客仍仅查看列表字段。

### 6.4 重新开启

- 只有发布者可重新开启自己发布的已完成或已撤销任务。
- 重新开启产生新一轮工作；上一轮的名单、要求、成果、验收和结束记录均保留。
- 上一轮通过结果不计入新一轮，新一轮需重新提交和验收。
- 公告任务原有执行成员默认保留，发布者可调整，并在重新开启时选择恢复领取或保持停止领取。
- 指定任务保留上一轮目标来源；小组来源重新按当前启用注册组员计算，直接指定来源仍按有效成员计算。
- 新一轮若无执行成员，应明确提示，不能凭旧轮通过结果立即完成。
- 原截止时间默认沿用；若已过期，提示发布者修改或清除，不因逾期阻止重新开启。
- 向本轮执行成员生成指派提醒，即使该成员上一轮已经参与，也需告知新一轮开始。

## 7. 站内消息与指派弹窗

### 7.1 消息对象

| 事件 | 提醒对象 |
| --- | --- |
| 新增指派、因入组加入任务、重新开启 | 本轮被指派的执行成员 |
| 成员主动领取 | 发布者 |
| 要求修改、执行对象调整、任务撤销 | 受影响成员；小组变化同时提醒发布者 |
| 成果提交或重提 | 发布者 |
| 验收通过或打回 | 逐人交付提醒对应成员；共同交付提醒当前执行成员 |
| 整体完成 | 发布者和本轮执行成员 |

成员只可访问自己的消息。不是给所有能查看任务的人群发消息；游客没有消息和未读状态。

### 7.2 弹窗

- 成员登录或进入网站后，检查本人未读的指派提醒。
- 多条提醒集中在一个弹窗中显示任务标题、发布者及任务入口，不连续弹出多个窗口。
- 点击“知道了”标记所展示指派提醒已读；点击某项“查看任务”仅将该项标记已读，并进入详情。其他条目仍保留未读状态。
- 已读状态保存在服务端；刷新、重新登录或换设备后，同一条已读提醒不再弹出。
- 读完仍可在消息列表查看。任务已撤销、成员已被移出或轮次已过期的指派提醒不再作为待办弹窗，但消息历史保留。
- 弹窗是通知，不增加接受、拒绝指派的流程；普通任务更新仅进入消息列表，不触发指派弹窗。

## 8. 页面能力

页面入口名称和能力在本节固定，具体路由在API和页面契约阶段确定。

| 页面或区域 | 主要能力 |
| --- | --- |
| 任务列表 | 全部任务、状态、类型、截止时间；注册成员可筛选“我发布的”“我执行的” |
| 游客任务列表 | 仅标题、发布者、截止时间、状态，无详情和成果入口 |
| 发布任务 | 填写要求、类型、交付模式、人数或指定对象、截止时间、任务附件 |
| 任务详情 | 当前轮要求、执行名单、来源、进度、成果和历史；按身份显示操作 |
| 成果提交区域 | 文字、链接、附件；重提时提示保存为新版本 |
| 验收区域 | 发布者查看最新版本、通过或填写原因打回 |
| 历史区域 | 查看各轮名单、要求变化、成果版本和验收反馈，不提供改写历史操作 |
| 站内消息 | 本人未读及历史消息，跳转对应任务 |
| 指派提醒弹窗 | 多条未读指派集中提醒、知道了、查看任务 |

默认中文，桌面及移动端可完成完整业务。文件输入、多人选择、验收按钮和提醒弹窗应适合手机操作；状态不只靠颜色表达。

2026-10-08界面补充：发布页宽屏分为任务内容、执行安排两栏，窄屏按单栏排列；表单文字及输入采用16px，辅助说明至少14px。全站现有下拉菜单共用主题化控件，提供选中标识、键盘方向键/回车/Esc/Tab和长名单滚动，在弹窗内不被裁切。任务截止时间改为日历选日期和独立时分输入，提供今天、明天、一周后与清空；选日期后的默认时间为18:00，未选日期仍不设置截止时间，始终按北京时间保存。删除、撤销、解散和转让确认窗口与其标题、提示、按钮居中，默认聚焦取消；这轮仅调整展示和交互，既有权限与业务状态规则不变。

## 9. 数据保留、兼容与维护

- 保留任务、各工作轮次、目标来源、执行人员变化、要求变更、成果版本、验收反馈、附件关联和消息已读状态。
- 发布、要求修改、执行对象调整、领取结束、提交、验收、打回、撤销和重新开启等关键写操作记录审计。
- 新增任务历史不得写入课程ScheduleVersion，也不得替换课程或课表导入草稿。

### 16.2 个人工作记录及权限

- 每条记录包含标题、说明和状态，支持多条记录。状态为“进行中、已完成、暂停”。
- 注册成员可以添加、修改、删除自己的记录；所有者由服务端会话确定，不接受客户端指定他人为所有者。其他成员、任务发布者和组长均不能修改或删除他人的记录。
- 所有注册成员可以查看其他成员的近期工作记录。游客和普通未登录访问者不能读取记录，包括接口、直接链接和隐藏的管理入口；原有游客课表权限保持不变。
- 对其他成员展示：全部进行中、暂停记录，以及最近7天完成的记录。暂停不表示结束，不因更新时间较早而隐藏。
- 本人管理时可以查看全部自己的记录，包括已完成超过7天的记录，并继续修改、删除。该完整管理范围不扩展给其他成员；接口不能通过筛选参数获得他人的完整旧记录。
- 删除前确认，明确提示无法恢复；确认后删除个人记录，不提供回收站或恢复入口。超过7天是退出近期展示范围，不是自动删除。
- 记录仅为文字，不增加文件上传、评论、额外消息提醒或特殊审核角色。现有任务附件、站内消息及验收流程继续沿用。

### 16.3 任务情况与近7天规则

- 展示该成员当前承担的进行中任务，以及近7天完成的任务；未领取的公告不算其承担的任务，已撤销任务不进入近期工作展示。
- 任务完成仍由原有发布者验收及整体完成规则决定。逐人模式中该成员已通过但整体尚未完成，仍属于进行中任务，可以同时展示该成员已通过的状态。
- “近一周”明确为查询时刻向前7×24小时的滚动区间，含区间起点和当前时刻，不按本周一重置。个人记录按其完成时间筛选，任务按任务完成时间筛选；普通文字修改不能把旧完成记录刷新成近期完成。
- 时间由服务端确定，界面按北京时间展示。进行中和暂停记录不受7天时间窗口限制。
- 任务展示保留详情入口，注册成员访问详情仍遵循原任务规则。空结果提示“暂无近期工作记录”或“暂无符合条件的任务”，不能据此断言该成员没有工作。
