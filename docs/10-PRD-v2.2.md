# HenuBCI v2.2 需求：站内消息清理

状态：2026-10-09已上线。确认范围和验收结果见[07](07-TASKS.md)。

本版只增加站内消息删除。关系图与 Jev 推荐属于 [V3 需求](11-PRD-v3.md)，不并入本版。现有任务及消息规则见 [v2 PRD](09-PRD-v2.md)，项目进度见 [07-TASKS.md](07-TASKS.md)。

## 1. 目标与范围

成员读过的消息较多时，能在现有“站内消息”页面清理不再需要的提醒。提供多选删除与一键删除已读消息；保留未读、刷新、分页、已读标记和任务跳转功能。

“当前已加载”指页面已经取得并展示的消息集合，包括用户点击“查看更早消息”后追加的消息；不是数据库内全部历史，也不是仅屏幕可见的几行。删除范围不得自动扩大到尚未加载的消息。

| 操作 | 明确行为 |
| --- | --- |
| 多选删除 | 只能选择本人已加载且已读的消息；可选择多条后确认删除 |
| 一键删除 | 按钮为“删除已加载的已读消息”，范围为当前已加载的全部本人已读消息，不要求逐条勾选 |
| 确认 | 提示实际条数、只删除消息且无法恢复；确认窗口沿用现有居中规范 |
| 取消 | 不删除任何消息，不改变已读状态 |
| 删除成功 | 已删除消息从列表消失，清除相关选择状态；刷新或其他设备再次读取时仍已删除 |
| 没有可删除项 | 不允许发起空操作，明确提示没有已读消息可删除 |

“一键”指直接选定上述范围，仍需确认，不绕过误删确认。删除后没有回收站、撤销或产品恢复入口；现有灾备不等同于个人消息恢复功能。

## 2. 权限与业务边界

- 服务端从会话确定接收人；成员只能删除自己的消息，任务发布者和组长均无权删除他人的消息。
- 未读消息不可选择或删除；删除接口同样验证已读条件，不能只依赖按钮是否隐藏或禁用。
- 游客和未登录访问者不可读取、标记或删除个人消息。不增加管理员或额外角色。
- 删除的是通知记录，不删除任务、工作轮次、成果、反馈、执行名单、任务变更历史或文件，也不等同于撤销任务或放弃领取。
- 本版不改变指派弹窗、已读标记及原任务权限。新到达的未读提醒不得被清理操作顺带移除。

## 3. 分页、并发与异常

确认集合、并发及失败处理：

- 打开确认窗口时固定本次目标消息集合，确认后不得重新扩大到随后加载或到达的消息。
- 点击“全选”仅选择已加载的可删除已读消息；清除全选不影响未读消息。
- 同一批消息已在另一个设备删除时，可收敛为“已清理”结果；重复请求不得影响其他消息。
- 请求混入他人的消息或仍存在的未读消息时，拒绝该批操作，不先删除其中合法部分；返回可处理的提示。
- 网络失败、授权失效或数据库失败不得让页面假装已删除；保留仍存在的数据，提示刷新或重新登录后重试。
- 清理后分页须继续可用，不因游标对应的消息删除而漏掉剩余历史；不得把“当前已加载”变成跨页全库删除。
- 消息内容和真实成员信息不写入普通错误日志；必要操作记录仅保留操作人、时间、数量等最小元数据。

| 编号 | 必须证明的行为 |

## 5. 兼容、发布与交接

保留现有课程、账号、小组、任务、附件和工作记录规则。不在本轮添加自动到期删除、清空所有历史、未读删除、回收站或站外通知。

原 [数据库文档](02-DATABASE.md) 和 [API 文档](03-API.md) 已补齐DELETE接口、授权、批次边界、错误及并发契约；实际验证另见进度记录。沿用 `web/src/app`、`web/src/components`、`web/src/lib` 和现有测试位置，不新增应用文件、依赖或迁移。

维护者负责备份、发布和回退；发布前验证成套备份可恢复，并保留旧应用。回退应用不承诺恢复用户已明确删除的消息，不删除卷或其他业务数据。发布必须另行记录实际结果。

默认出处见[决策包](09-v2-grill-decision-packet.yaml)的`message_cleanup_v22_20261009`。
