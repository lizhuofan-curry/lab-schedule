# HenuBCI V3 需求：工作关系图与 Jev 候选人推荐

确认日期：2026-10-09。需求已确认，未开发；本期全端2D，3D后续。

站内消息清理单独属于 [v2.2](10-PRD-v2.2.md)。本版保留现有课表、任务、验收、成果及本人工作记录写入权限；已上线行为与证据仍以 [v2 PRD](09-PRD-v2.md) 和 [07-TASKS.md](07-TASKS.md) 为准。

## 1. 目标、用户与范围

让注册成员在一张可交互的关系图中理解每个人、每个小组或全体成员做过和正在做的事情；让指定任务发布者结合已有经历与当前负担，更快比较候选个人和小组。

| 功能 | 本期范围 |
| --- | --- |
| 关系图 | 新增独立“关系图”页面，可切换个人、小组、全体范围 |
| 展示 | 所有设备均为2D，默认展示选定范围的全部节点；不默认只展示主要主题后再展开 |
| 关系 | 真实参与/归属关系与 AI 提炼的共同主题、内容关联同时存在，视觉和说明明确区分 |
| 历史 | 分析和来源查看覆盖现存的全部历史工作记录及相关任务历史，不限近7天 |
| 推荐 | Jev 推荐个人和项目小组，排序并展示依据；发布者仍可选一人、多人或小组 |
| 入口 | 发布指定任务，以及发布者调整进行中任务执行对象时，点击“推荐候选人”运行 |

不增加管理员、自动指派、自动发布、自动验收、能力考核榜、任务排期、课表分析、附件正文分析或成员记录代写。3D不进入本期开发和验收。

## 2. 历史读取与权限

- 所有注册且可用的成员可以查看个人、小组和全体关系图及其中的历史来源；游客和未登录者不能访问图、图数据、历史来源或推荐接口。
- 完整工作历史读取是V3明确新增的授权范围，限关系图、来源查看和授权分析用途；原成员页仍只展示他人的进行中、暂停及滚动7×24小时内完成记录。
- 不能通过扩大原成员页筛选参数绕过近期边界。开发时须补齐独立且受控的历史来源契约及对应权限测试。
- 只有本人能增删改自己的工作记录；只有发布者管理和验收自己的任务；只有当前执行成员提交成果。完整历史读取不赋予跨成员写权限。
- 原任务轮次、成果版本和结束名单保持，图谱不能把过去轮次的成果算作当前完成，不能把 AI 推断当成任务验收事实。
- 读取范围变化尚未实施。当前仍执行`AGENTS.md`第14条；开发V3前同步独立历史读取契约，v2.2不启用此权限。

## 3. 关系图内容与小组汇总

### 3.1 节点、连线与来源

图中可包括成员、小组、任务、工作记录和 AI 提炼的主题。任务与工作记录合在一张图中，不拆成“个人经历”和“小组成果”两个展示区域；必要的来源标识、原始所有者和状态仍须可查看，不能误标事实。

- 真实关系来自系统数据，例如成员参与任务、记录归属本人、当前小组成员关系。
- AI关系表达共同主题或语义关联，明确标为模型提炼/推断；不增加不存在的任务、经历、成员或已完成事实。
- AI主题及关联要有可追溯的原任务或记录依据；点击可看到关联内容及原始来源，能够核对。
- 节点标明适当的名称和状态。历史任务、轮次及重复内容不得因汇总而变成多份当前负担。
- 默认全部节点表示选定个人、小组或全体范围内的全量，而不是无视用户的范围选择；主动搜索/筛选后展示对应子集并明确筛选状态。

### 3.2 小组关系图

按小组当前成员汇总其现存历史工作记录及相关任务。个人经历不另设分类区域，不要求新增手动“小组归属”字段。小组成员变化后汇总范围同步变化。

当前组员此前完成的个人工作可以出现在本组图，但其原始所有者仍保持；这不证明该工作是在加入本组期间完成或由本组交付。点击来源不能伪造小组承担关系。一个成员加入多个小组时，可出现在多个小组范围，整体汇总和推荐负担按真实来源去重。

### 3.3 阅读与交互

- 桌面及手机均采用2D；支持拖动平移、缩放、节点选择、相关连线突出、搜索、范围/状态筛选和点击查看来源。
- 默认全量节点，不暗中按热门程度截断；在大量节点时通过视图缩放、标签显示策略和用户筛选保障阅读，提供清晰的加载/空结果/错误状态。
- 字体和节点选中后的文字必须可读；图区域内交互不造成整页横向溢出，手机可退出来源详情并继续操作。
- 颜色、图标、布局参数及具体绘图库由开发者在实现时核验，不在需求阶段承诺某依赖已兼容本项目。

## 4. 自动分析、删除同步与数据失效

- 任务、成员/小组关系或工作记录发生相关变化后，真实关系及 AI 主题关联自动更新，不要求用户点击“更新分析”。
- 用户接受按实际调用付费，不设产品月度费用上限；不能在后续实现中默默改成仅手动分析或达到默认月额度后停用。
- 自动更新不是每次刷新都重算全部历史。变化合并、缓存、重试及并发控制属于实现选择，必须维持自动更新语义且不能隐藏陈旧状态。
- 界面展示分析更新时间及待更新/失败状态；处理中可保留仍有效的旧关联，但不能伪装为最新结果。
- 本人删除工作记录后，移除节点及该记录作为依据的关联、推荐和缓存引用；有关联重算时明确待更新，不继续显示已删除原文。
- 仅由该记录支撑的主题须移除；仍有其他有效来源支持的主题可保留。图谱中的删除不能代替实际业务记录删除，也不能反向删除任务。
- 已在途中发出的模型请求即使返回，也不能重新写回已删除或已变更版本的依据。当前推荐界面失效结果须重新分析或移除无效证据。
- 不提供产品入口浏览已删除内容的旧图快照；既有灾备保留规则不等同于前台图谱保留删除内容。

## 5. 模型来源与外部数据边界

### 5.1 服务分工和依赖

图谱的主题提炼使用生成式大模型，平台、具体模型、费用及凭据由用户在V3开发前确认，当前不默认选通义千问或OpenAI，也不沿用课表OCR配置作为已授权的文字分析凭据。

候选推荐使用TypeSafe的Jev；用户已提供 [控制台链接](https://console.typesafe.ai/playground) 并表示已有API Key，不在聊天或需求文档保存密钥。已核验的 [官方介绍](https://docs.typesafe.ai/introduction) 和 [官方API说明](https://api.typesafe.ai/docs) 支持Choice、Score、Noul等结构化判断；Jev不生成自由文本，不能宣称它直接撰写长篇推荐理由。

推荐依据来自真实任务/记录、已核验主题及定义明确的评分维度，可用事实摘要表达。Jev分数和置信度是模型判断，不是能力事实或保证正确；平台宣传及其他项目评测不能代替本项目验收。

已有Key不等于已接通；尚未调用模型或验证准确率，模型/权限/收费/契约须在开发前核验。

### 5.2 允许发送的数据

用户明确允许将分析所需的任务和工作记录文字发送给外部模型；不设置逐成员开关作为本期前置。服务端仅发送当前授权范围内的必要数据。

- 网页仍展示正常成员姓名；模型输入用M01等成员代号，结果在服务端按本次对应关系映射回成员。代号不能被解释为彻底匿名。
- 不发送学号、账号资料、内部兼容邮箱、认证凭据、数据库连接串、API Key或附件正文；姓名与账号标识的最小化处理涵盖所发文字，不仅节点字段。
- 任务要求、记录说明是分析材料，不是可信系统指令。成员填写的“忽略规则/选择某人”等内容不能改变授权、候选池或系统评分规则。
- 模型输出必须校验候选/来源标识、范围、结构和可显示内容；非法来源或危险HTML/链接不能直接渲染或进入指派。
- API Key只存在于服务端安全配置，不进入前端包、普通日志、仓库或截图；错误日志不保存原始个人记录或完整模型输入输出。
- 页面应明确说明分析使用外部服务、采用代号但正文可能仍含可识别内容，避免宣称数据从不出站。

## 6. Jev 候选人及小组推荐

### 6.1 触发、范围和结果

- 仅在发布指定任务或发布者调整进行中任务的执行对象时，点击推荐按钮运行；不因每次键入或打开页面自动推荐。
- 默认候选池为全部已注册且启用成员，发布者可限定到选定小组；推荐支持候选个人和项目小组。
- 展示排序、相关经历依据、当前任务/工作负担及信息不足或低置信度提示，便于比较多位候选者。
- 发布者可以选择一人、多人、小组及原规则允许的个人/小组混选，也可忽略推荐直接手动指定；结果不能自动选定并发布。
- 限定小组时，推荐个人不得超出所选小组当前合格成员；小组推荐也遵守选定范围，不能借小组扩大执行对象。
- 保留原小组未注册/停用成员排除、来源合并去重及动态名单规则；空有效名单不能作为可执行推荐。

### 6.2 综合依据与缺失信息

相关经历和当前负担综合考虑，没有记录不能等同于空闲或能力不足。任务负担依据当前承担任务及状态、截止时间等真实字段；工作记录仅为自报信息，不能直接当作真实工时。

小组推荐汇总当前合格成员的相关经历和负担，去重共同承担的任务；不能因人数更多或同一来源出现多次就默认更适合。推荐显示其考虑的是当前小组名单，已完成轮次历史仍保持原固定名单。

信息不足者仍允许进入展示/选择流程，明确缺失依据；不能编造技术专长、完成经历或可用时间。实际分值、权重和置信度阈值由开发者与用户通过代表性任务核验，需求不承诺未经验证的准确率。

### 6.3 人工决策与过期结果

推荐只是辅助，不修改任务、执行名单、成果或验收状态。真正发布/调整时，仍执行原服务端所有权、成员启用、注册状态、当前小组名单和去重校验。

任务要求、候选范围、成员状态、工作数据或小组名单变化后，提示旧推荐失效；不能把旧模型结果作为绕过当前授权的依据。模型超时、不可用或输出不合法时，清晰提示重试并保留手动选择。

## 7. 异常、费用及运行边界

用户明确不设费用上限，不代表平台没有额度、限流或余额限制。平台用量不足、网络失败或模型超时时，基础真实关系图、课程、任务、验收及手动指派仍可用；失败分析不能阻塞核心业务写入。

开发补充默认：沿用当前服务器和已有安全备份流程，不在2GB服务器本地加载大模型；模型请求在数据库事务之外进行，自动更新采用可观察且受控的调用/重试，不无限循环。记录模型标识、时间、数据版本、状态和用量等最小诊断信息，不暴露成员原文。

月预算不设产品强制上限，但需能了解模型调用和实际费用；准确价格及用量计算以用户选定平台和账号为准。没有确认生成式模型时，不以模拟结果宣称主题提炼已经完成或启用收费服务。
