# 同频课表产品需求文档（MVP-A）

版本：1.0  
状态：开发基线  
日期：2026-09-27

## 1. 产品目标

为实验室成员提供一个易上手的网页工具，用于：

1. 查看任意已注册成员在指定教学周的课表。
2. 查询某天全天没课或指定节次没课的成员。
3. 选择多位成员或全体成员，查找可用于分配任务、讨论和开会的共同空闲时间。
4. 让每位成员直接在网页上维护自己的课表，不强制上传 Excel。

系统不在 MVP-A 中管理任务内容、会议室、通知或教务数据同步。

## 2. 用户与权限

### 2.1 成员

- 使用名册中的姓名、学号和自设密码注册。
- 使用学号和密码登录。
- 查看所有启用成员的课表、课程详情和空闲状态。
- 查看实验室名册的注册进度和未注册名单。
- 只可新增、修改、删除自己的课程。
- 不可查看他人的账号资料、操作日志或源文件。

系统不设置管理员账号或角色，所有注册成员权限平等。实验室名册、学期和节次作为部署初始化数据维护，不提供日常管理后台。

### 2.2 匿名用户

- 只能访问登录和注册页面。
- 不可查看任何成员课表。

## 3. 分阶段范围

### 3.1 MVP-A：首个可上线版本

- 部署时初始化实验室成员名册、学期和节次。
- 姓名＋学号＋密码自助注册；学号＋密码登录。
- 注册统计与未注册名单复制。
- 学期、教学周和每日节次时间配置。
- 网页直接新增、编辑、删除本人课程。
- 必填、周次、节次和时间冲突校验。
- 查看任意成员的周课表。
- 查询全天没课、指定节次没课的成员。
- 查询多人的共同空闲和至少连续 N 节的时间段。
- 服务端权限校验、关键操作审计、响应式布局。
- PostgreSQL 持久化、Docker Compose、Caddy HTTPS 和备份脚本。

### 3.2 MVP-B：批量导入与版本

- 固定模板 `.xlsx` / `.csv` 下载与上传。
- 解析、逐行校验、冲突提示、预览、差异确认。
- 用户确认前不修改当前课表。
- 确认整表替换时生成不可变的完整课表 Snapshot。
- 历史版本和 Diff 只读查看；不提供一键回退。

### 3.3 v1

- 任意表头映射、`.xls`、完整版本回退。
- 停课、补课、调课和调休。
- 成员分组、标签、导出和受控分享链接。
- 更完整的审计和公开范围配置。

### 3.4 暂不实现

- 图片/PDF 课表 OCR。
- 教务系统自动同步。
- 自动建会、通知和会议室预订。

## 4. 核心流程

### 4.1 注册

项目上线前预置成员姓名与学号。名单收集期间允许先录入姓名并将学号标记为“待补”，但该成员在学号补齐前不能注册。成员输入姓名、学号和密码；系统仅在姓名与启用名册精确匹配、且该名册项尚未绑定账号时完成注册。一个学号只能注册一次。

### 4.2 网页维护课表

成员进入“我的课表”，点击空白格添加课程，点击课程卡片编辑；填写课程名、星期、节次和周次，教师、地点、备注可选。保存成功后，其他成员看到的课表与空闲状态立即更新。

#### 4.2.1 当前学期固定上课时间

当前学期为 `2026–2027 学年第一学期`，第 1 周从 `2026-08-31` 开始，共 18 周。网页和数据库必须使用以下时间，不得自行推算或调整：

| 节次 | 时间 | 节次 | 时间 |
|---|---|---|---|
| 第1节 | 08:00–08:45 | 第8节 | 15:55–16:40 |
| 第2节 | 08:55–09:40 | 第9节 | 17:00–17:45 |
| 第3节 | 10:00–10:45 | 第10节 | 17:55–18:40 |
| 第4节 | 10:55–11:40 | 第11节 | 19:10–19:55 |
| 第5节 | 11:45–12:30 | 第12节 | 20:05–20:50 |
| 第6节 | 14:05–14:50 | 第13节 | 20:55–21:40 |
| 第7节 | 15:00–15:45 |  |  |

`12:30–14:05` 为午休时间，不创建“中午1节”或“中午2节”，也不可在课程表单中选择。数据库只保存第 1–13 节。

### 4.3 查看成员课表

登录成员从成员列表搜索并选择一人，再选择学期与教学周，系统只显示该周实际生效的课程。

### 4.4 查找空闲

用户选择日期、成员范围和需要的连续节数。系统计算当天有效课程占用，返回全天没课成员、指定节次没课成员及所有被选成员的共同空闲连续区间。

## 5. 核心业务规则

- **BR-01 身份绑定**：一个成员最多绑定一个账号，一个账号最多绑定一个成员。
- **BR-02 学号唯一**：学号在整个系统中唯一，登录时大小写与首尾空格规范化。
- **BR-03 课程所有权**：成员只能写入自己的课程；所有权由服务端会话判断，不接收客户端指定的所有者。
- **BR-04 周次标准化**：单双周和范围只是输入形式，写入前必须转成具体教学周数组，如 `[1,3,5]`。
- **BR-05 时间冲突**：同一成员两门课程星期相同、周数组有交集且节次区间重叠时构成冲突，默认阻止保存。
- **BR-06 重复记录**：课程名、星期、节次、周次等完全一致为 Duplicate，不重复写入并提示。
- **BR-07 共同空闲**：共同空闲等于有效节次全集减去所有被选成员占用节次的并集。
- **BR-08 连续节次**：只返回共同空闲集合中长度大于等于 N 的连续区间，不能跨过被占用节次拼接。
- **BR-09 全天没课**：某成员在目标日期的有效课程集合为空，即为全天没课。
- **BR-10 学期边界**：目标日期不在学期日期范围内时不计算，返回明确提示。
- **BR-11 审计与版本**：网页 CRUD 写入 AuditLog；MVP-B 的确认批量导入生成完整 ScheduleVersion Snapshot。

## 6. 页面

| 页面 | 主要内容 |
|---|---|
| `/login` | 学号、密码登录 |
| `/register` | 姓名、学号、密码注册 |
| `/dashboard` | 今日/本周概况、成员搜索、快速查看课表 |
| `/my-schedule` | 网格添加、编辑、删除本人课程 |
| `/members` | 搜索成员并查看其课表 |
| `/availability` | 没课成员、共同空闲和连续节次查询 |
| `/registration` | 所有登录成员查看注册统计和未注册名单 |

MVP-A 不创建管理后台、导入页面和版本回退页面。

## 7. 易用性与状态

- 用户进入“我的课表”即可通过“点击空白格添加、点击课程修改”完成维护。
- 课程表单用自然语言标签，不要求理解数据库字段。
- 删除前二次确认；保存成功给出明确反馈。
- 空状态说明下一步操作；错误信息说明原因和解决办法。
- 手机端支持横向滚动课表，主要操作按钮可触达。
- 颜色不是唯一状态线索，课程卡同时显示文字。

## 8. 验收重点

1. 预置 10 人名册后显示总数 10、已注册 0；一人注册后所有登录成员均看到已注册 1、未注册 9、注册率 10%。
2. 名册外身份、姓名学号不匹配和已注册学号均被拒绝。
3. A 可以查看 B 的课表，但任何参数篡改都不能修改 B 的课程。
4. 同周同节冲突被阻止；不相交周次允许占用同一节次。
5. A、B、C 共同空闲只返回三人均无课的节次，连续 N 节算法结果正确。
6. 50 名活跃用户规模下主要查询保持流畅，至少使用 100 名成员、每人每学期 100 条课程做基础验证。
7. 桌面和手机浏览器均可完成注册、录课、查看和空闲查询。
