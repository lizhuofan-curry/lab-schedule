# HenuBCI V3.1需求：DeepSeek内容关联与同课关系

确认日期：2026-10-09。用户通过grill-me逐轮选择并最终确认A。本文件定义需求，不代表功能已经开发、模型验收通过或正式分析已开启；当前进度与发布证据只维护在[07-TASKS.md](07-TASKS.md)。

本版继承[V3](11-PRD-v3.md)的只读图谱、现存历史来源、权限、2D交互及删除失效规则。以下范围覆盖旧版的“AI分析全部历史”和“不分析课表”约定；不改动原课表、任务、小组及工作记录的业务写权限。完整决策见[确认记录](12-v3.1-grill-decision-packet.yaml)。

## 1. 目标与范围

让注册启用成员在现有关系图中看见彼此正在做或暂时暂停的工作、当前任务之间的内容联系，以及课表安排一致的同课关系。DeepSeek解释内容关联，系统核验事实，不能用模型输出制造参与、完成、能力或到课事实。

| 数据 | V3.1分析用途 | 范围 |
| --- | --- | --- |
| 工作记录 | 内容相近、同方法及有明确依据的上下游关联 | 进行中、暂停的现存记录；已完成不参与新增AI分析 |
| 任务 | 与工作记录或其他任务的内容关联 | 进行中的任务及当前轮次；完成、撤销及旧轮次不参与新增AI分析 |
| 成员与小组 | 帮助模型理解原始所有者、发布者、实际承担者和当前组员 | 注册启用成员，使用代号；小组结构按实际名单，不推断历史归属 |
| 课表 | 用户指定的同课条件核对与解释上下文 | 当前学期的现存课程；仅课程名、周次、星期、起止节次、教室及必要成员代号 |
| 历史来源 | 保留既有节点、真实关系及来源查看 | 延续V3授权，不能把旧经历算作当前承担 |

不新增AI主题节点、成员间AI内容线、小组间AI内容线、执行人推荐、自动指派、课程主题提炼、能力评价、实际到课判断、共同空闲分析、任务排期、附件正文分析或3D。AI输入包含必要小组和课表上下文，不等于允许生成任意种类的关系。

## 2. AI内容关联

新增细虚线连接工作记录／任务节点，包括工作—工作、工作—任务、任务—任务。成员继续经本人记录、发布、实际承担等真实关系连接，不把内容相似自动翻译成成员共同参与。

允许的关联：研究内容相近、明确使用同一方法，或原文支持的上下游关系。上下游关系必须说明方向；同主题／同方法不表示上下游，也不表示有合作意愿。系统角色和小组名单不能替代内容证据，例如同属一个小组不自动证明两项工作相关。

每条AI线必须提供：两端来源标识、关联类型、简短理由、两端可核对的文字依据、分析时间及输入版本。上下游另外标明方向。点击线显示解释和原始来源，不要求用户自行沿成员归属线寻找依据。

证据不足时不连线；不为了图更密、接近圆形或满足评价数量而生成关联。同一来源不能与自身关联，重复线合并；不得引用不存在、已删除、已完成退出分析范围或当前用户无权读取的来源。模型输出的来源、关系类型、文本和结构必须服务端校验，不直接渲染HTML或危险链接。

发布者、当前承担者、历史参与者、曾参与已退出必须作为不同事实保留；文字声称参与不能覆盖任务系统记录。模型不新增经历、不确认完成、不改业务记录。

## 3. 同课关系

同课线直接连接成员，不新增课程节点，采用真实关系的细实线。出现连线必须同时满足：

1. 课程属于同一个当前学期。
2. 星期相同，具体周次集合有交集；不能仅比较“周二第3节”而忽略周次。
3. 起止节次完全相同，部分时间重叠不匹配。
4. 课程名称相同。
5. 教室相同且非空；缺少教室不能当成“同一教室”。

连线含义是“课表安排一致”，不证明成员实际共同到课，也不证明相同教师或课程班级。单双周按已经展开的具体周次集合核对，不跨学期混算。无需要求课程教师字段相同，也不将教师发送模型。

点击线展示所有支持该成员对的匹配课程、共同周次、星期、完整节次和教室；同一成员对有多门匹配课时汇总证据，不能重复叠线。现有小组等不同真实关系仍保留其含义。

课程名／教室只允许保守的空白规范化；默认不由模型把简称、不同楼宇或相似教室合并为同一个值。具体规范化需在实现前补齐契约和正反例，不能弱化“相同”标准。源课表更新或删除后，同课线按当前数据更新，核心课程写入权限不变。

必要课表字段允许供DeepSeek读取，但同课关系由系统准确计算并核验；模型无权新增不符合以上条件的课程联系，也不得扩大到课程语义、空闲、能力或排期推断。

## 4. 展示与交互

关系图入口打开即进入铺满浏览器可用窗口的沉浸式二维画布，不显示网站侧栏、页标题、外框或常驻筛选／说明栏。左上角保留返回总览入口，右上角固定设置按钮，设置默认关闭，展开为覆盖画布的浮动面板，不挤压或重排画布。面板以可折叠的筛选、颜色组、外观、力度和图例／来源分区呈现，使用浅灰底、细分隔和紫色滑块。复用全体／个人／小组范围、搜索、状态筛选、节点列表、图例和分析状态；颜色组按成员／小组／工作／任务类别调整。外观提供节点大小、连线透明度、名称渐隐阈值、线宽和重播自然展开；力度提供向心、排斥、相连吸引与连线长度，调整时保留现有节点位置并重新收敛。设置仅影响当前页面显示，不修改来源或模型结果。Esc关闭设置并将焦点返回按钮；选择节点或连线收起设置并显示浮动详情，手机详情位于底部，面板可独立滚动。首次打开全量节点由紧凑种子位置自然展开，透明度在约900ms内渐入，力导向逐渐收敛；数据轮询不重复入场，新增节点参与现有布局。系统启用减少动态效果时直接显示稳定完整图。参考Obsidian示例，成员绿、工作红、任务紫、小组橙，文字中性灰，普通连线浅灰、悬停关联紫色；保留真实实线／模型虚线的语义，不因配色增加关系。不将该入场效果称为按创建时间播放的历史时间轴动画。默认全量自然圆形云团，保持完整实心圆、节点基准半径3.2px起、按连接数量递增且最大8px，桌面默认显示倍数1.7（初始屏幕半径5.44～13.6px），手机窄屏（小于768px）默认0.8（初始屏幕半径2.56～6.4px）；手动调整后保留当前选择、细线、文字在线条上层、节点避让、滚轮缩放、平移、拖动与手机双指缩放；画布及节点文字禁止浏览器文本选择，按下阻止默认选择，来源详情文字仍可复制。不增加恢复或加减按钮。

真实线和AI线均保持0.6px，高亮只改变颜色和明暗，不变粗；实线／虚线及图例明确区分事实和推断。点线查看关系详情时，手机可关闭详情返回图；节点来源查看继续可用。多人、任务或关系较多时不得暗中丢弃来源或截断全量节点。

范围筛选只展示当前图中有效两端的AI联系。状态筛选不改变任务或记录实际状态。完成工作或结束任务后退出新增AI分析，其历史节点及真实线继续按V3和用户筛选展示。

## 5. 自动更新与失效

工作文字／状态、当前任务文字／轮次／承担关系、成员启用情况、小组名单、当前学期或课表等相关输入变化后自动更新，不要求点击“更新分析”。通常从有效业务修改成功到新AI联系可见在2分钟内；这是正常平台响应下的目标，不承诺外部模型超时也能达成。

连续修改可合并，同版本复用结果，不因页面刷新或每15秒轮询重复付费分析。不应因无人打开关系图而永久停止更新。事实变化无需等待模型完成即可读取；页面维持已有自动读取机制，手动“重新读取”立即获取当前结果而非强制重新调用模型。

结果绑定当前输入版本，版本变化后不得继续把旧AI线当作当前结果展示。显示待更新／失败及分析时间；涉及删除、范围退出、失效成员或权限收回时，先移除失效节点、线、证据和已打开详情。途中旧请求返回不得恢复旧内容、覆盖新结果或重新泄露原文。

外部超时、限流、余额不足或输出校验失败时，保留真实关系图及核心业务，并提供可处理的提示；允许有界退避重试，不无限重试。同课关系不依赖DeepSeek成功。费用继承V3按实际调用计费、不设产品月度强制截断的已确认约定；仍须观察调用量、用量和错误。

## 6. 数据与权限边界

沿用独立图谱和来源授权：只有注册启用成员可读取，游客、匿名拒绝；原成员页读取他人工作仍受近期窗口限制，不扩大任何写权限。新增AI详情和反馈接口同样服务端鉴权，禁止客户端伪造成员身份。

继续采用已选DeepSeek服务与独立服务端DEEPSEEK_API_KEY；既有实现配置为deepseek-flash，实际接口兼容性及返回模型标识在联调时验证，不把配置名当作已验证的官方能力。本次需求确认允许后续按本文必要范围进行外部分析，不等于本次立即发送正式数据或启用收费调用。

模型输入采用成员／小组代号，保留必要角色关系；工作与任务标题、说明发送前最小化姓名及账号标识。课表仅发送第1节列出的字段；不发送学号、账号、邮箱、教师、课表备注、附件正文、密码、凭据、数据库连接串、删除原文或审计快照。代号不是彻底匿名，正文及课程安排仍可能可识别，页面须明确告知外部分析的数据范围。

来源文字、课程名、教室和反馈都是不可信材料，其“忽略规则”等内容不能改变系统指令、授权或分析范围。不得把反馈正文自动追加到模型提示词。日志仅保留必要版本、耗时、用量、错误类别及模型标识，不记录个人原文或完整模型输入输出；密钥仅服务端安全配置。

## 7. 不准确关联反馈

所有注册启用成员可针对当前可见AI联系提交“不准确”反馈并填写理由。反馈关联成员会话、线及其输入版本；不得通过伪造ID反馈他人不可见来源。理由需校验长度和空白，重复提交需避免无意义重复。

反馈只是用户判断，不立即删除、隐藏或改变公共连线，也不改任何任务／记录。无管理员角色、无成员投票自动裁决和自动纠正；维护者根据证据用于后续模型规则或质量改进，成员权限仍平等。

默认提交成功后明确提示“已记录，不会立即修改公共关系图”；反馈不作为公开评价某成员的内容，不默认向全体暴露提交者与理由。用户在当前会话可确认自己的提交结果，本期不增加反馈管理后台或工单状态流转。线失效后反馈仍只能保存必要标识／版本，不保存已删除来源原文或可访问旧内容的快照。

AI人工评价覆盖同主题、同方法、明确上下游、弱证据、暂停工作、角色不同、小组重叠及提示注入。合理性按源内容能够支持理由判断，不以图更密或模型自评分验收。评价记录标明模型、版本、样本、判定与真实API证据；由开发者准备、用户与维护者人工核对。

正式来源不足以组成样本时，用有明确答案并标识为测试的合成数据补足，不在正式站制造测试业务数据，不宣传为全部正式数据准确率。30条正向联系不能排除漏连风险，另用已知应关联的典型案例检查漏连；不另虚构未确认的召回率门槛。零结果或不足30条不能直接宣布质量通过。

## 9. 发布、维护与待实现契约

本次交付只定义需求。实现前把数据／API、索引及迁移、版本范围、课程规范化、反馈存储和有界重试契约分别补充到既有02／03／05文档。数据库变更须评估索引与迁移；不得把现有单纯themes输出直接当作本版内容关联验收通过。

继续在原项目目录开发；2GB正式服务器只加载本地Linux镜像。功能代码默认关闭，图谱和分析开关分离。上线前需新一轮代码测试、真实接口人工质量验收、成套备份恢复及正式桌面／手机验收；本需求确认不代替发布验收或直接开启正式分析。

可先保留真实图关闭AI能力，故障时停止AI调用及推断结果而保留授权真实关系和核心业务。回退不删除课程、任务、工作记录、附件及卷；旧缓存不得绕过当前权限或数据版本。维护者负责凭据、平台余额、失败监测和反馈复核，不新增产品管理员。
