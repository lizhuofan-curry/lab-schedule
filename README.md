# 同频课表

### 为实验室和课题组找到真正能约在一起的时间

集中维护成员课表，按教学周准确计算个人空闲、指定时段空闲成员和多人共同空闲；支持标准模板、复制表格、河大课表同步和图片识别草稿。

课表页面默认打开北京时间对应的当前教学周，并突出显示今天的表头与整列；手机端横向课表会自动定位到今天，切换到其他周后不会保留错误的“今天”标记。

同频课表不是另一张只能“看”的课程表。它面向实验室里最常见的时间协作问题：**谁在某个教学周没课、指定时间谁能参加、几个人何时同时有空、单双周是否真的冲突，以及成员怎样安全地提交整张课表。**

项目坚持三个原则：课表写入只能由本人完成；空闲结果必须遵守真实教学周和节次；任何整表替换都要先预览、再确认、可追踪。

## 为什么做这个项目

群聊里反复问“明天下午谁有空”，通常会遇到三类问题：每个人描述课表的方式不同；单双周和临时筛选容易算错；收齐答案后仍然需要人工求交集。同频课表把这些过程变成统一、可复核的业务规则。

- **面向协作，不止展示**：从成员课表直接计算个人、多人和指定时段的可用时间。
- **中文优先，操作直接**：页面、表单、错误提示和部署文档均以中文呈现，手机端可使用。
- **数据归属清晰**：登录成员可以查看团队课表，但只能修改自己的课程；系统没有隐藏的管理员特权。
- **导入不会突然覆盖**：文件、复制表格、河大同步或图片识别都先生成草稿与预览，确认后才在短事务中替换本人课表。
- **适合小团队自托管**：应用、PostgreSQL 和 Caddy 可通过 Docker Compose 部署，团队掌握自己的数据。

## 怎样选择课表导入方式

| 你现在拥有的资料 | 建议入口 | 是否需要教务凭据 | 是否会调用第三方 | 当前建议 |
| --- | --- | --- | --- | --- |
| 可按模板整理的结构化课程 | Excel / CSV 标准模板 | 否 | 否 | **最稳定**，适合批量维护和可重复导入 |
| Excel 表格或教务结果页 | 复制表格 | 否 | 否 | **最省操作**，请保留表头并核对组合时间地点 |
| 河大统一认证账号 | 河大课表同步 | 是，仅当次请求 | 会访问河大教务系统 | **河大用户优先**，预览无误后再确认 |
| 课表截图或照片 | 服务器本地 OCR | 否 | 否 | **隐私优先**，必须逐项人工复核 |
| 布局复杂的彩色网格课表 | 千问智能识别 | 否 | 明确同意后发送当次图片 | **待真图验收**，失败时改用本地 OCR |

无论从哪个入口开始，系统都不会在“读取或识别”时直接覆盖课表。最终写入仍需通过字段校验、冲突检查、差异预览和本人确认。

## 适用场景

这个项目更适合成员规模不大、彼此需要频繁协调时间的实验室、课题组和学生团队。

### 临时约讨论时间

选择需要参加的成员、一个教学周和星期，再按需限定起止时间与最短空闲分钟数。系统只返回所有人同时空闲的区间；单双周课程、课间和午休都会参与计算。

### 找某个时间段有空的人

指定教学周、星期和起止时间，系统返回在该时间窗口全程没有课程的成员。还可以先按年级缩小范围，适合安排值班、招募临时协助或组织分组活动。

### 查看某位成员何时有空

选择一名成员、教学周和星期，可以看到空闲节次、真实开始与结束时间，以及按课时累计的分钟数；还可限定查询起止时间。

### 集中收集实验室课表

成员可以点击课表网格逐条维护，也可以上传标准 Excel / CSV 模板，或从 Excel、教务结果页复制带表头的课表。河南大学成员还可使用仅限当次请求的凭据读取本人课表。这些已验收的整表导入都先展示错误、冲突和增删差异，只有本人确认后才会替换当前课表。

### 把课表截图变成可编辑草稿

图片可通过点击选择、从微信等桌面软件拖入，或复制后粘贴到上传区。系统先在服务器本地识别文字，再把可能的课程生成草稿卡片，并醒目标出缺失或低置信度的课程名、星期、节次、周次、教师和地点；用户可以修改、删除或补充候选，然后再进入冲突与差异预览。若来源软件没有向浏览器提供真实图片文件，页面会提示改用粘贴或先保存原图。

## 从注册到协作

1. **部署者初始化基础数据**：准备当前学期、13 个有效节次和允许注册的成员名册。
2. **成员完成身份绑定**：成员使用名册中的姓名、学号和自设密码注册；名册外身份、姓名学号不匹配和已绑定学号都会被拒绝。
3. **成员维护本人课表**：通过网页逐条增删改，或使用标准模板、复制表格、河大课表同步、图片识别生成导入预览。
4. **服务端执行规则校验**：根据登录会话确定所有者，并检查学期、周次、节次、重复课程和时间冲突。
5. **团队查看最新结果**：其他登录成员可以立即查看更新后的周课表，并使用个人、多人或时间段空闲查询。
6. **系统保留追踪记录**：网页 CRUD 写入审计日志；确认整表导入还会保存一个不可变的完整课表快照。

## 单教学周的空闲时间怎样计算

当前检索表单固定使用“单个教学周 + 单个星期 + 可选起止时间 + 最短空闲分钟数”。系统以当前学期的节次表、成员课程和具体周次计算，不使用简单的课程数量估算。日期范围、节次范围和“最少连续 N 节”不是当前页面条件。

### 1. 先确定教学周和星期

用户选择当前学期中的一个教学周和星期。服务端再校验周次是否在学期范围内，并换算出对应日期供结果展示；超出学期时会返回明确错误。

### 2. 只保留当周真正生效的课程

课程的周次在写入前已经展开为具体数组。例如“1–8 周单周”会存成 `[1, 3, 5, 7]`。查询第 4 周时，这门课程不会占用时间；查询第 5 周时才会参与计算。

### 3. 计算个人或多人的占用并集

- 查某个人时，只扣除该成员在所选周次和星期真正生效的课程节次。
- 查多人共同空闲时，先合并所有所选成员的占用节次，再从有效节次全集中取补集。
- 按时间找人时，成员必须在与所选时间窗口重叠的每一个节次中都没课才会被返回。

### 4. 生成连续空闲区间

系统只合并节次编号连续且没有课程打断的区间，再应用“至少 M 分钟”条件。持续分钟数取自节次表中的真实上下课时间，课间和午休不会被计入可用时长。

例如某成员第 1、2、4 节空闲，第 3 节有课：

- 系统会生成“第 1–2 节”和“第 4 节”两个独立区间；
- 第 4 节不会与第 1–2 节拼接；
- 设置最短空闲分钟数后，再根据各节真实授课时长过滤结果。

## 课表采集、导入与版本记录

当前有四种课表采集入口，成熟度并不相同：

| 来源 | 读取方式 | 成熟度 | 写入前保障 |
| --- | --- | --- | --- |
| 标准 Excel / CSV | 系统模板固定包含课程、教师、地点、星期、节次、周次、备注和颜色 | MVP-B 已验收 | 文件大小、表头、字段、重复、冲突与差异校验 |
| 复制表格 | 从 Excel 或教务结果页粘贴带表头的文本，识别常见列名及组合时间地点 | MVP-B 已验收 | 最大 10 万字符；一门课的多个上课安排可拆成多条课程 |
| 河大教务系统 | 当前登录成员提供仅用于当次请求的密码，系统读取并解析本人课表 | MVP-B 真实账号已验收 | 会话学号必须与教务身份一致，密码不持久化，失败时不改库 |
| 课表图片 | 上传最大 8 MB 的 PNG、JPG 或 WebP，在服务器本地运行 OCR 并生成可编辑草稿 | v1 第一阶段 | 图片与 OCR 原文不持久化；低置信度字段人工复核；确认前不改库 |

四种来源最终都共用“预览—确认”两阶段：

1. **预览阶段**：解析课程，检查字段、周次、节次、重复和冲突，并计算相对当前课表的新增、保留与删除项目。即使是河大课表，读取成功也只生成预览，不写数据库。
2. **确认阶段**：服务端重新校验预览数据和当前学期，只在全部数据有效时，用导入结果替换当前登录成员的本学期课表。

确认成功后会在同一个短事务中完成：

- 创建新的 `ScheduleVersion`；
- 保存该版本的完整 `CourseSnapshot`；
- 替换本人当前学期课程；
- 追加对应的 `AuditLog`。

版本历史目前用于只读核对，不提供一键回退。网页逐条添加、编辑或删除课程只记录审计日志，不创建整表版本。

## 图片识别导入怎样工作

图片识别被设计为“帮用户少录一些”的草稿工具，而不是自动覆盖课表的黑盒。

1. **上传与校验**：登录成员上传 PNG、JPG 或 WebP；文件必须非空且不超过 8 MB。
2. **临时识别**：服务器使用 Tesseract.js 与简体中文模型提取文本行、位置和整体置信度，不把图片或 OCR 原文写入数据库。
3. **候选草稿**：系统尝试提取课程名、教师、地点、星期、开始节次、结束节次和周次。缺失或待复核字段会以高对比样式显示。
4. **人工修正**：用户对照左侧原图修改、补全、新增或删除候选。整体文字置信度只是参考，不代表星期、节次和周次已经正确。
5. **差异预览与确认**：修正后的草稿重新进入服务端字段、重复、冲突和差异校验。只有当前会话成员明确确认后，才替换本人课表并创建 `image` 来源的历史版本。

### 为什么必须人工复核

传统 OCR 擅长“看到字”，但彩色课表网格还需要理解文字属于哪个星期、哪几节、哪些周次。合并单元格、浅色背景、裁剪不完整和手机拍照倾斜都会降低结构还原准确率。因此，v1 保留原图对照、待复核标记和人工修改。可选千问适配层已接入代码，但在真实图片验收前仍不作为稳定能力。

| 持久化 | PostgreSQL | 保存账号、名册、学期、节次、课程、审计日志和课表快照 |
| 对外入口 | Caddy | 终止 HTTPS、反向代理应用并设置基础安全响应头 |

一次写请求的完整链路是：浏览器提交数据，Route Handler 从会话确认当前成员，Zod 校验字段，服务层在短事务中执行权限与业务规则，Drizzle 写入 PostgreSQL，最后接口向前端返回结果或带处理建议的中文错误。页面层不直接访问数据库，外部网络调用不进入数据库事务。

### 核心数据关系

- 一个 `User` 最多绑定一个 `Student`，一个 `Student` 最多绑定一个账号。
- 一个成员在一个学期可以拥有多条 `Course`。
- 一个学期拥有独立的日期范围、教学周数和 `Period` 节次表。
- `AuditLog` 记录课程写操作的操作者、动作与变更前后值。
- 一次确认导入创建一个 `ScheduleVersion`，并关联这份版本中的全部 `CourseSnapshot`。

数据库字段、约束和索引的完整说明见 [数据库设计](docs/02-DATABASE.md)。接口路径、权限和错误码见 [API 设计](docs/03-API.md)。

### 关键 API 索引

| 能力 | 接口 | 写库时机 |
| --- | --- | --- |
| 本人课程 CRUD | `GET/POST /api/my/courses`、`PATCH/DELETE /api/my/courses/:id` | 单条写操作立即生效，并写审计日志 |
| 单周空闲查询 | `POST /api/availability/query` | 只读 |
| 标准文件预览 | `POST /api/my/schedule-import/preview` | 不写库 |
| 复制表格预览 | `POST /api/my/schedule-import/text-preview` | 不写库 |
| 图片识别 | `POST /api/my/schedule-import/image-ocr` | 只返回临时草稿，不写库 |
| 图片草稿校验 | `POST /api/my/schedule-import/image-preview` | 只返回冲突与差异，不写库 |
| 河大课表读取 | `POST /api/my/henu-sync` | 只生成本人预览，不写库 |
| 统一确认导入 | `POST /api/my/schedule-import/confirm` | 在短事务中替换本人课表、创建版本快照并写审计日志 |

所有上述接口都依赖服务端会话确定当前成员。导入确认接口不接受客户端指定的 `student_id`，避免通过篡改请求替他人覆盖课表。

## 关键业务规则

1. 登录成员可以查看所有启用成员的课表，但只能写自己的课程。
2. 服务端从会话确定课程所有者，禁止信任请求体或上传文件中的成员标识。
3. 自助注册必须匹配未绑定账号的预置名册项。
4. 周次写入前展开为具体 `smallint[]`；冲突要求星期相同、周次相交且节次重叠。
5. 共同空闲是有效节次全集减去所有所选成员占用节次的并集；连续空闲不能跨占用节次拼接。
6. 网页单条 CRUD 只写审计日志；只有确认整表导入才创建版本与完整快照。
7. 河大同步学号必须等于会话成员学号；密码只用于当前请求，外部网络读取不放进数据库事务。
8. 图片识别只生成临时草稿；图片与 OCR 原文不持久化，未确认不得修改课表，确认后仍只能写当前会话成员。

更完整的验收口径见 [产品需求文档](docs/01-PRD.md)。

## 安全与数据边界

- `.env`、数据库连接串、认证密钥、备份文件和构建产物不得提交到 Git。
- 生产环境必须使用不同的强随机值配置 `POSTGRES_PASSWORD` 与 `BETTER_AUTH_SECRET`。
- 不在客户端包、日志、截图或 Issue 中暴露真实姓名、学号、课表和访问凭据。
- 河大教务密码只在当次请求中使用，不写数据库、浏览器存储、日志、版本快照或审计详情。
- 教务系统登录失败、出现验证码或页面结构变化时安全失败，确认之前不修改当前课表。
- 图片及 OCR 原文只在当前请求和浏览器页面中使用，不进入数据库、版本快照或审计日志。
- 选择千问智能识别时，页面必须在发送图片前告知去向并获得本次明确同意；密钥只能保留在服务端。
- 部署或公开仓库前，应审查非默认 seed 脚本和测试数据，确认其中不含真实个人信息。
- 恢复数据库必须使用显式确认变量；不要执行会删除数据卷的 `docker compose down -v`。

## 常见问题

### 为什么所有成员都能查看其他人的课表？

这是当前产品的核心协作规则：实验室内部的登录成员共享启用成员的课表，用于协调工作和共同时间。匿名用户不能查看任何成员课表，成员也不能修改他人的课程。

### 为什么没有管理员？

MVP-B 采用平等成员模型，避免把普通业务操作集中到某个账号。名册、学期和节次属于部署初始化数据，不通过日常网页维护。若未来确实需要受控管理后台，应单独设计权限边界，而不是让普通成员账号隐式获得管理员能力。

### 为什么不能直接上传任意学校课表文件？

当前支持系统提供的固定 Excel / CSV 模板，也能识别从 Excel 或教务结果页复制的常见表头和组合上课时间；另外对河南大学提供了一条经过验收的专用同步通道。v1 的图片识别用于从截图生成待人工修正的草稿，并不代表已兼容图片所属学校的专用文件或登录流程。其他学校的专用格式与身份认证仍需基于真实样例单独适配。

### 河大同步会保存教务密码吗？

不会。密码只用于当次读取请求，不持久化、不写日志，也不进入课表快照。读取结束后页面只保留可供本人核对的课程预览；未点击确认时，数据库不会发生课表变更。

### 上传的课表图片会被保存吗？

不会。当前本地 OCR 链路会把图片发送到自托管应用服务器进行当次识别，但图片与 OCR 原文不写入数据库、文件存储、历史版本或审计日志。只有经人工修正并确认的结构化课程会被保存。

### 为什么 OCR 置信度很高仍然要检查？

OCR 整体置信度主要表示文字像不像被正确读出，不能证明这段文字已经归到正确的星期、节次和周次。因此页面会保留原图对照和字段级待复核标记，最终以用户确认后的结构化课程为准。

### 本地 OCR 没有识别出课程怎么办？

优先使用教务系统导出的原图，裁掉无关导航栏、边框和大面积空白，保持图片正向且文字清晰。如果仍无法生成可用候选，可以在草稿页面手动新增课程，或改用复制表格与标准模板。

### 为什么智能识别提示尚未配置？

千问识别是可选能力。部署者需在服务端配置 `SCHEDULE_VISION_PROVIDER`、`SCHEDULE_VISION_MODEL`、`DASHSCOPE_API_KEY` 和 `DASHSCOPE_BASE_URL`，并确保 Key、模型和地域地址匹配。未配置或外部服务不可用时，本地 OCR 仍可独立使用。

### 为什么单条修改没有历史版本？

单条 CRUD 已通过 `AuditLog` 保留变更记录。`ScheduleVersion` 表示一次完整课表导入快照，只在本人确认整表导入时创建，避免把每次微小编辑都误认为可独立恢复的整表版本。

### 可以直接把数据库端口开放到公网吗？

不可以。生产环境应只通过 Caddy 暴露 `80/443`，PostgreSQL 保持在容器内部网络或服务器 loopback。远程维护数据库时应使用受控的 SSH 隧道或其他安全通道。

- 不得把课程所有者从客户端请求中直接写入；新增导入方式必须复用当前会话成员授权。
- 新的解析器、OCR 或模型接入必须先生成可编辑草稿，不得绕过预览和确认直接改库。
- 不要在代码、提交记录、Issue、测试快照或截图中提交真实密钥、教务密码、数据库连接串与成员私密数据。
- 至少运行 `npm run lint`、`npm test` 和 `npm run build`；修改权限、导入或事务逻辑时，还应运行 `npm run test:integration`。
- 在交付说明中分别报告静态检查、自动化测试、浏览器验收和生产部署，不用其中一项代替另一项。
