# 同频课表

### 为实验室和课题组找到真正能约在一起的时间

集中维护成员课表，按教学周准确计算个人空闲、指定时段空闲成员和多人共同空闲；支持标准模板、复制表格导入、河大课表安全同步、版本快照与自托管部署。

同频课表不是另一张只能“看”的课程表。它面向实验室里最常见的时间协作问题：**谁在某个教学周没课、指定时间谁能参加、几个人何时同时有空、单双周是否真的冲突，以及成员怎样安全地提交整张课表。**

项目坚持三个原则：课表写入只能由本人完成；空闲结果必须遵守真实教学周和节次；任何整表替换都要先预览、再确认、可追踪。

## 为什么做这个项目

群聊里反复问“明天下午谁有空”，通常会遇到三类问题：每个人描述课表的方式不同；单双周和临时筛选容易算错；收齐答案后仍然需要人工求交集。同频课表把这些过程变成统一、可复核的业务规则。

- **面向协作，不止展示**：从成员课表直接计算个人、多人和指定时段的可用时间。
- **中文优先，操作直接**：页面、表单、错误提示和部署文档均以中文呈现，手机端可使用。
- **数据归属清晰**：登录成员可以查看团队课表，但只能修改自己的课程；系统没有隐藏的管理员特权。
- **导入不会突然覆盖**：文件、复制表格或河大同步都先生成预览，展示错误与差异，确认后才在短事务中替换本人课表。
- **适合小团队自托管**：应用、PostgreSQL 和 Caddy 可通过 Docker Compose 部署，团队掌握自己的数据。

## 适用场景

这个项目更适合成员规模不大、彼此需要频繁协调时间的实验室、课题组和学生团队。

### 临时约讨论时间

选择需要参加的成员、一个教学周和星期，再按需限定起止时间与最短空闲分钟数。系统只返回所有人同时空闲的区间；单双周课程、课间和午休都会参与计算。

### 找某个时间段有空的人

指定教学周、星期和起止时间，系统返回在该时间窗口全程没有课程的成员。还可以先按年级缩小范围，适合安排值班、招募临时协助或组织分组活动。

### 查看某位成员何时有空

选择一名成员、教学周和星期，可以看到空闲节次、真实开始与结束时间，以及按课时累计的分钟数；还可限定查询起止时间。

### 集中收集实验室课表

成员可以点击课表网格逐条维护，也可以上传标准 Excel / CSV 模板，或从 Excel、教务结果页复制带表头的课表。河南大学成员还可使用仅限当次请求的凭据读取本人课表。三种整表导入都先展示错误、冲突和增删差异，只有本人确认后才会替换当前课表。

## 从注册到协作

1. **部署者初始化基础数据**：准备当前学期、13 个有效节次和允许注册的成员名册。
2. **成员完成身份绑定**：成员使用名册中的姓名、学号和自设密码注册；名册外身份、姓名学号不匹配和已绑定学号都会被拒绝。
3. **成员维护本人课表**：通过网页逐条增删改，或使用标准模板、复制表格、河大课表同步生成导入预览。
4. **服务端执行规则校验**：根据登录会话确定所有者，并检查学期、周次、节次、重复课程和时间冲突。
5. **团队查看最新结果**：其他登录成员可以立即查看更新后的周课表，并使用个人、多人或时间段空闲查询。
6. **系统保留追踪记录**：网页 CRUD 写入审计日志；确认整表导入还会保存一个不可变的完整课表快照。

## 单教学周的空闲时间怎样计算

当前检索表单固定使用“单个教学周 + 单个星期 + 可选起止时间 + 最短空闲分钟数”。系统以当前学期的节次表、成员课程和具体周次计算，不使用简单的课程数量估算。日期范围、节次范围和“最少连续 N 节”不是当前页面条件。

### 1. 先确定教学周和星期

用户选择当前学期中的一个教学周和星期。服务端再校验周次是否在学期范围内，并换算出对应日期供结果展示；超出学期时会返回明确错误。

### 2. 只保留当周真正生效的课程

课程的周次在写入前已经展开为具体数组。例如“1–8 周单周”会存成 `[1, 3, 5, 7]`。查询第 4 周时，这门课程不会占用时间；查询第 5 周时才会参与计算。

### 3. 计算个人或多人的占用并集

- 查某个人时，只扣除该成员在所选周次和星期真正生效的课程节次。
- 查多人共同空闲时，先合并所有所选成员的占用节次，再从有效节次全集中取补集。
- 按时间找人时，成员必须在与所选时间窗口重叠的每一个节次中都没课才会被返回。

### 4. 生成连续空闲区间

系统只合并节次编号连续且没有课程打断的区间，再应用“至少 M 分钟”条件。持续分钟数取自节次表中的真实上下课时间，课间和午休不会被计入可用时长。

例如某成员第 1、2、4 节空闲，第 3 节有课：

- 系统会生成“第 1–2 节”和“第 4 节”两个独立区间；
- 第 4 节不会与第 1–2 节拼接；
- 设置最短空闲分钟数后，再根据各节真实授课时长过滤结果。

## 课表导入、河大同步与版本记录

当前有三种整表导入来源：

| 来源 | 读取方式 | 写入前保障 |
| --- | --- | --- |
| 标准 Excel / CSV | 系统模板固定包含课程、教师、地点、星期、节次、周次、备注和颜色 | 文件大小、表头、字段、重复、冲突与差异校验 |
| 复制表格 | 从 Excel 或教务结果页粘贴带表头的文本，识别常见列名及“上课时间 / 上课地点”组合字段 | 最大 10 万字符；一门课的多个上课安排可拆成多条待导入课程 |
| 河大教务系统 | 当前登录成员提供仅用于本次请求的密码，系统读取并解析本人课表 | 会话学号必须与教务身份一致，密码不持久化，失败时不改库 |

三种来源都共用“预览—确认”两阶段：

1. **预览阶段**：解析课程，检查字段、周次、节次、重复和冲突，并计算相对当前课表的新增、保留与删除项目。即使是河大课表，读取成功也只生成预览，不写数据库。
2. **确认阶段**：服务端重新校验预览数据和当前学期，只在全部数据有效时，用导入结果替换当前登录成员的本学期课表。

确认成功后会在同一个短事务中完成：

- 创建新的 `ScheduleVersion`；
- 保存该版本的完整 `CourseSnapshot`；
- 替换本人当前学期课程；
- 追加对应的 `AuditLog`。

版本历史目前用于只读核对，不提供一键回退。网页逐条添加、编辑或删除课程只记录审计日志，不创建整表版本。

## 技术架构

| 领域 | 技术 |

| UI | Tailwind CSS、Lucide React、中文响应式界面 |

### 各层职责

| 层次 | 目录或组件 | 责任边界 |
| --- | --- | --- |
| 页面与交互 | `web/src/app`、`web/src/components` | 展示中文界面、收集输入、调用接口和呈现可操作的错误信息 |
| 身份认证 | Better Auth、`server-auth.ts` | 使用学号登录，从服务端会话解析当前成员身份 |
| HTTP 接口 | `web/src/app/api` | 检查登录状态、使用 Zod 校验请求、调用业务服务并映射错误码 |
| 业务服务 | `web/src/lib/*-service.ts` | 实现课程所有权、冲突、空闲、导入、版本和事务规则 |
| 教务适配 | `henu-client.ts`、`henu-schedule-parse.ts` | 在数据库事务之外登录河大教务系统，读取并解析本人课表 |
| 数据访问 | `web/src/db`、Drizzle ORM | 定义表、约束、关系和数据库连接，不承载页面逻辑 |
| 持久化 | PostgreSQL | 保存账号、名册、学期、节次、课程、审计日志和课表快照 |
| 对外入口 | Caddy | 终止 HTTPS、反向代理应用并设置基础安全响应头 |

一次写请求的完整链路是：浏览器提交数据，Route Handler 从会话确认当前成员，Zod 校验字段，服务层在短事务中执行权限与业务规则，Drizzle 写入 PostgreSQL，最后接口向前端返回结果或带处理建议的中文错误。页面层不直接访问数据库，外部网络调用不进入数据库事务。

### 核心数据关系

- 一个 `User` 最多绑定一个 `Student`，一个 `Student` 最多绑定一个账号。
- 一个成员在一个学期可以拥有多条 `Course`。
- 一个学期拥有独立的日期范围、教学周数和 `Period` 节次表。
- `AuditLog` 记录课程写操作的操作者、动作与变更前后值。
- 一次确认导入创建一个 `ScheduleVersion`，并关联这份版本中的全部 `CourseSnapshot`。

数据库字段、约束和索引的完整说明见 [数据库设计](docs/02-DATABASE.md)。接口路径、权限和错误码见 [API 设计](docs/03-API.md)。

## 快速开始

先获取代码：

```bash
git clone https://github.com/lizhuofan-curry/lab-schedule.git
cd lab-schedule
```

### 方式一：本地开发

前置条件：Node.js 24、npm，以及一个可访问的 PostgreSQL 数据库。

```powershell
cd web
Copy-Item .env.example .env
npm ci
npm run db:migrate
npm run db:seed
npm run dev
```

开始前请编辑 `web/.env`：

```dotenv
DATABASE_URL=postgresql://schedule:你的密码@localhost:5432/schedule
BETTER_AUTH_SECRET=至少32位的随机字符串
BETTER_AUTH_URL=http://localhost:3000
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

然后访问 [http://localhost:3000](http://localhost:3000)。首次注册前，需要先把允许注册的成员姓名与学号写入 `students` 名册表。

### 本地启动后的检查清单

1. 打开 `/api/health`，确认应用可以访问数据库。
2. 使用名册中的姓名和学号注册一个测试成员。
3. 登录后添加一门只在部分周次生效的课程。
4. 在成员课表页切换教学周，确认课程只在目标周显示。
5. 在空闲查询页选择成员、教学周和星期，核对时间窗口与最短空闲分钟数是否生效。
6. 如需测试文件导入，先下载系统生成的模板；河大成员也可以在“我的课表”中只读预览同步结果，核对无误后再确认。

### 方式二：Docker Compose 部署

前置条件：Docker Engine、Docker Compose，以及已经解析到服务器的正式域名。

```bash
cd web
cp .env.production.example .env
# 编辑 .env，填写域名、数据库密码和 Better Auth 密钥
docker compose up -d --build
docker compose ps
```

Compose 会依次启动 PostgreSQL、执行迁移与初始化，再启动 Next.js 和 Caddy。正式环境只应开放 `80/443`；PostgreSQL 仅绑定服务器本机的 `127.0.0.1:5433`，不要暴露到公网。

完整上线、备份和恢复步骤见 [部署与运维文档](docs/04-DEPLOYMENT.md)。

```text
│  ├─ test/                   权限和未登录访问集成测试
│  ├─ drizzle/                SQL 迁移与 schema 快照
│  ├─ scripts/                初始化、测试成员、备份与恢复脚本
│  ├─ compose.yaml            app + postgres + caddy 编排
│  └─ Dockerfile
└─ AGENTS.md                  当前开发阶段与不可偏离规则
```

## 测试与质量保障

项目把纯业务规则测试与需要数据库的集成测试分开，便于快速反馈，也避免把“构建成功”误报成“部署成功”。

| 验证 | 覆盖重点 | 是否需要数据库 |
| --- | --- | --- |
| `npm run lint` | TypeScript / React 代码规范和常见问题 | 否 |
| `npm test` | 周次展开、课程冲突、空闲区间、模板与复制表格解析、年级归类和河大课表网格解析 | 否 |
| `npm run test:integration` | A 查看 B、A 不能修改 B、未登录拒绝、文件 / 粘贴导入隔离、河大同步身份与凭据边界 | 是，使用独立测试库 |
| `npm run build` | TypeScript 检查、Next.js 生产编译和页面生成 | 视环境配置而定 |

空闲相关测试至少应持续覆盖：单双周课程、被课程打断的非连续空闲、跨学期日期、多人占用并集和真实分钟数。权限测试必须始终从服务端会话所有权出发，不能只验证前端是否隐藏按钮。

### 提交前建议

```bash
cd web
npm run lint
npm test
npm run test:integration
npm run build
```

生产构建通过只说明代码能够完成本地生产编译；真正的部署完成还需要分别核对容器状态、数据库迁移、健康接口、HTTPS 和浏览器关键流程。

## 关键业务规则

1. 登录成员可以查看所有启用成员的课表，但只能写自己的课程。
2. 服务端从会话确定课程所有者，禁止信任请求体或上传文件中的成员标识。
3. 自助注册必须匹配未绑定账号的预置名册项。
4. 周次写入前展开为具体 `smallint[]`；冲突要求星期相同、周次相交且节次重叠。
5. 共同空闲是有效节次全集减去所有所选成员占用节次的并集；连续空闲不能跨占用节次拼接。
6. 网页单条 CRUD 只写审计日志；只有确认整表导入才创建版本与完整快照。
7. 河大同步学号必须等于会话成员学号；密码只用于当前请求，外部网络读取不放进数据库事务。

更完整的验收口径见 [产品需求文档](docs/01-PRD.md)。

## 安全与数据边界

- `.env`、数据库连接串、认证密钥、备份文件和构建产物不得提交到 Git。
- 生产环境必须使用不同的强随机值配置 `POSTGRES_PASSWORD` 与 `BETTER_AUTH_SECRET`。
- 不在客户端包、日志、截图或 Issue 中暴露真实姓名、学号、课表和访问凭据。
- 河大教务密码只在当次请求中使用，不写数据库、浏览器存储、日志、版本快照或审计详情。
- 教务系统登录失败、出现验证码或页面结构变化时安全失败，确认之前不修改当前课表。
- 部署或公开仓库前，应审查非默认 seed 脚本和测试数据，确认其中不含真实个人信息。
- 恢复数据库必须使用显式确认变量；不要执行会删除数据卷的 `docker compose down -v`。

## 当前阶段与边界

当前稳定实现范围为 **MVP-B**。标准 CSV、复制表格和河大同步均已走通“预览—确认—当前课表—历史版本”的浏览器流程；腾讯云、域名、HTTPS、定时备份和恢复演练仍待完成，在这些生产验证完成前不把“本地构建通过”描述成“已经上线”。

以下能力不属于当前稳定范围：

- 其他学校的教务系统专用格式或登录同步；
- 课程表图片识别；
- 历史版本回退；
- 匿名公开课表；
- 调休、停课、补课等日期例外；
- 消息与日程通知；
- 管理员角色和网页名册管理。

河大课表同步已完成一次性凭据读取、本人身份校验、解析预览、确认写库、版本快照、审计和自动化权限测试，并已使用真实河大账号完成“读取预览—核对差异—确认替换—保存版本”的浏览器验收。复制表格是通用辅助导入，不等同于支持任意学校的专用导出文件或登录流程；历史版本页面也只是只读快照，不应描述为可恢复备份。

## 常见问题

### 为什么所有成员都能查看其他人的课表？

这是当前产品的核心协作规则：实验室内部的登录成员共享启用成员的课表，用于协调工作和共同时间。匿名用户不能查看任何成员课表，成员也不能修改他人的课程。

### 为什么没有管理员？

MVP-B 采用平等成员模型，避免把普通业务操作集中到某个账号。名册、学期和节次属于部署初始化数据，不通过日常网页维护。若未来确实需要受控管理后台，应单独设计权限边界，而不是让普通成员账号隐式获得管理员能力。

### 为什么不能直接上传任意学校课表文件？

当前支持系统提供的固定 Excel / CSV 模板，也能识别从 Excel 或教务结果页复制的常见表头和组合上课时间；另外对河南大学提供了一条经过验收的专用同步通道。不同学校和教务系统的专用文件、身份认证、节次与周次格式仍然差异很大，因此其他学校的专用格式、登录同步和图片识别不属于当前 MVP-B。

### 河大同步会保存教务密码吗？

不会。密码只用于当次读取请求，不持久化、不写日志，也不进入课表快照。读取结束后页面只保留可供本人核对的课程预览；未点击确认时，数据库不会发生课表变更。

### 为什么单条修改没有历史版本？

单条 CRUD 已通过 `AuditLog` 保留变更记录。`ScheduleVersion` 表示一次完整课表导入快照，只在本人确认整表导入时创建，避免把每次微小编辑都误认为可独立恢复的整表版本。

### 可以直接把数据库端口开放到公网吗？

不可以。生产环境应只通过 Caddy 暴露 `80/443`，PostgreSQL 保持在容器内部网络或服务器 loopback。远程维护数据库时应使用受控的 SSH 隧道或其他安全通道。
